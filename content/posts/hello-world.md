这是第一篇文章。

写东西这件事，拖了很久。一部分原因是懒，另一部分原因是我一直觉得「等我把博客搭好再开始写」——而搭博客本身又是一件可以无限打磨的事。

所以这次反过来：先把骨架搭起来，能跑、能看、能发布，然后立刻开始写。

## 这里是什么

一个静态博客。没有数据库，没有后台程序，没有评论区的实时轮询，也没有任何第三方追踪脚本。

写文章就是在 `content/posts/` 里新建一个 Markdown 文件，然后执行一次构建命令，得到一个纯静态的 `public/` 目录。把这个目录扔到任何静态托管上，站点就活了。

```powershell
node build.js
node serve.js
```

## 为什么不用现成的

WordPress、Hexo、Hugo 都能做同样的事。我选自己写一个几百行的生成器，理由不只是"想练手"，实际算下来有三个好处：

1. **没有依赖**。不用维护 Node 包的版本，不用担心某个插件三年不更新。只要 Node 还能跑，它就还能用。
2. **完全可控**。模板、样式、输出结构、`.html` 的每一个字节都是我能读懂的。出了问题能自己修。
3. **好迁移**。Markdown 文件在哪里都是 Markdown。哪天想换 Hugo 或 Astro，把 `content/posts/` 拷过去就行。

代价也很清楚：没有现成的插件生态，评论、统计这类功能要自己接。目前我只接了最必要的，以后需要再说。

## 打算写什么

- **技术**：踩过的坑、读过的源码、工具的使用方式，尽量写成"以后的我"能看懂的样子
- **读书**：读完之后的笔记，重点不是复述内容，而是想清楚自己得到了什么
- **生活**：值得记下来的小事，不为了凑数

不打算追热点，也不打算为了让搜索引擎喜欢而写。真诚一点，写慢一点。

## 关于更新的节奏

计划每周一篇。这个频率不高，但对一个业余写作者来说，能稳定做到比偶尔爆发更重要。

如果某周没写，我会在归档里看出来——这大概也算一种自我监督。

## 现在就开始

这篇文章写完，博客就正式启用了。接下来要做的事是：把剩下的占位内容换掉，写上自己的名字和介绍，然后开始写第二篇。

模板和代码都在这个仓库里，需要的读者可以直接拿走用。
