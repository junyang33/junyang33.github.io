每次跟人聊起自建博客，几乎都会绕到「用 WordPress 还是静态」这个问题上。争论常常变成技术品味之争，但我觉得它本质上是个成本问题。

## 一次访问的差别

动态博客的每个请求都要走一遍：路由 → 查数据库 → 渲染模板 → 拼装 HTML → 返回。访客越多，服务器越忙。

静态博客在**发布时**就把这一步做完了。访客拿到的是一份写好的文件，服务器（或者 CDN）只需要把它递出去。

差别不在于"能不能实现"，而在于你每天要维护什么。

## 把成本摊开

| 成本项 | 静态 | 动态 |
| --- | --- | --- |
| 服务器 | 不需要，或只要静态托管 | 一台常开的机器，还要续费 |
| 补丁 | 几乎不用管 | 核心、插件、主题都得跟 |
| 备份 | `git push` 就是完整备份 | 数据库 + 上传目录分开备份 |
| 攻击面 | 没有数据库、没有后台、没有可执行代码 | 后台、插件、上传接口都是入口 |
| 流量 | CDN 直出，几乎免费 | 加缓存、调配置，否则容易挂 |
| 扩容 | 复制文件 | 升配、加缓存、拆服务 |

大多数个人博客的日访问量在三位数以下。这个量级下，动态博客换来的一切灵活性都用不上：不要会员，因为只有作者一个；不要多作者协作，因为就一个人写；不要实时评论，接个第三方就行。

## 静态真正的三个不便

老实讲，也不是没有代价：

**一、发布要构建。** 改完文章得跑一次命令，等几十秒。习惯了 Ctrl+S 就上线的人会觉得别扭。

**二、没有后台。** 写作依赖编辑器和文件系统。出门在外想改个错字，得先有那台机器。

**三、动态功能要外挂。** 评论接 Giscus，搜索靠客户端索引，统计用 Umami。每一样都得单独配置。

前两个可以靠脚本和习惯抹平，第三个躲不掉——但也就那么几个功能。

## 我的判断

如果你**每周能写一篇，也打算写三年以上**，静态方案的综合成本更低：钱少、心少、被攻击的概率低。

如果你**还没确定能不能坚持**，别急着搭基础设施。先在现成平台上写十篇，看看自己是不是真的想写。为了一个可能荒废的博客先花两周搭环境，是最常见的浪费。

## 一个容易被忽略的好处

静态博客的"慢"是可控的慢：构建需要时间，但访问是快的；动态博客的"快"是表面的快：发布快，但每次访问都在花服务器的钱。

对一个长期维护的个人站来说，前者更健康。
